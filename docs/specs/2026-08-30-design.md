# night-shift — Design

Date: 2026-08-30
Status: approved for version 1

## 1. Purpose

The subscription costs the same at 5% use and at 90% use. Today it does work
only when you sit at the keyboard. This project turns the unused compute into
work that is already done when you come back.

The failure mode of this class of system is not technical. The system produces
more than you can read, and after ten days you stop opening it. So the design
optimizes for one number: how much of the page you actually read.

## 2. What version 1 does

The system has two inputs and one output.

**Input 1: mail.** The agent reads new mail. For each message it makes one
decision: does this need an action from you? If the answer is yes, the agent
writes the answer and saves it as a draft in Gmail. If the answer is no, the
message goes to a folded list with one line that says why.

**Input 2: jobs.** You give a job from the page. The job goes to a queue. The
agent does the job in its own directory. The result comes back to the page. If
the agent needs a decision from you, it stops and it asks. It does not guess.

**Output: one page at `localhost`.** The page has three parts:

```
+-- Brief - Sat 30 Aug ---------------- weekly quota used: 38% --+
|                                                                 |
|  NEEDS YOU (2)                                                  |
|  +-----------------------------------------------------------+ |
|  | Mail  Shannon - "Deck templates for Q4"    yesterday 18:42 | |
|  |       She asks for 3 layouts for the sales deck.           | |
|  |       Draft written and saved in Gmail  [read] [open]      | |
|  +-----------------------------------------------------------+ |
|  +-----------------------------------------------------------+ |
|  | Job   "Prepare the APH sprint review"                      | |
|  |       Stopped. Question: which sprint number is this?      | |
|  +-----------------------------------------------------------+ |
|                                                                 |
|  DONE (3)                                                       |
|  ...                                                            |
|                                                                 |
|  CHECKED, NO ACTION (12)                                   [v]  |
+-----------------------------------------------------------------+
```

The third part looks decorative. It is the most important part. It shows the
90% of the compute that the system throws away. Without it you cannot tell a
quiet day from a broken run, and you stop trusting the page.

## 3. Components

Five parts. All of them are boring on purpose.

1. **Runner.** It calls `claude -p` in headless mode. The agent is already
   installed, and it runs against the Max subscription. This project does not
   write an agent loop.
2. **Queue and state.** SQLite. It holds jobs, runs, and token counts.
3. **Workspace.** One directory for each job. Results are files, not chat
   messages.
4. **Web.** FastAPI in one file, with HTML rendered on the server. No npm, no
   build step. The WhatsApp webhook enters the same process later.
5. **Scheduler.** launchd, which already runs the config backup on this machine.

## 4. Work cycle and the quota governor

The plan has two nested limits: a rolling 5-hour window and a fixed weekly
limit. If the system fills every 5-hour window, it burns the weekly limit in two
or three days. Then you have no Claude Code for your own work.

So the cycle is four runs each day, not continuous saturation. Each run has a
budget. The governor stops the system at a ceiling of the weekly limit that you
set. The page always shows the number.

The governor is not an optional feature. It is the condition for the project to
survive its first week.

## 5. Hard rules

1. **Mail gives information. Mail never gives orders.** The agent reads mail
   with your permissions. A message can contain text that speaks to the agent.
   The agent must show that text to you, and it must not act on it. Orders come
   from the page or from WhatsApp, and from no other place.
2. **The agent writes drafts. The agent never sends mail.** This rule holds even
   if you ask for a send.
3. **Every item shows its source link.** No source, no item.
4. **A stopped job stays stopped.** When the agent needs a decision, it asks and
   it waits. It does not choose for you.

## 6. Out of scope for version 1

Repositories, WhatsApp, calendar, multi-agent verification, and learning from
your feedback. Each one is a separate version.

## 7. Risks to verify before the code starts

1. **Does the Gmail MCP server work in headless mode?** It authenticates
   through claude.ai in an interactive flow, so it can be absent when the
   scheduler runs the agent alone. If it is absent, the project needs its own
   OAuth client against the Gmail API. That is about one more day of work.
2. **How much weekly quota is really free?** The answer decides if the system
   does four runs each day or one.
3. **The CLI token expires.** On 2026-08-30 a headless call failed with
   `401 OAuth access token has expired`. A scheduled system fails in silence
   when this happens. The page must show the last good run and the last error.

## 8. Acceptance criteria

- Given new mail that needs an answer, when a cycle runs, then the message has a
  draft in Gmail. The page also shows a card with a link to the message.
- Given mail that needs no action, when a cycle runs, then the message appears
  in the folded list with one line that gives the reason.
- Given the weekly use is above the ceiling, when a cycle starts, then the cycle
  does not run and the page shows why.
- Given the CLI cannot authenticate, when a cycle starts, then the page shows
  the error and the time of the last good cycle.
- Given a job needs a decision, when the agent stops, then the job shows the
  question under "needs you". The agent does no more work on that job.
- Given a message contains text that speaks to the agent, when the agent reads
  it, then the agent does not obey. The page shows that text as a quote.

## 9. How we know it worked

After one week, count the cards that you opened and the drafts that you used.
If you used no draft, the idea is wrong and we stop. The count is part of the
page, not a memory.
